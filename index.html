Project 2 Enhancements

What We Added

🔐

Security Hardening

Enabled HTTPS automatically via GitHub Pages. Added a strict Content Security Policy, XSS sanitization on the contact form, honeypot anti-bot field, and client-side rate limiting.

  • HTTPS / TLS via GitHub Pages
  • Content Security Policy (CSP)
  • X-Frame-Options: DENY
  • XSS input sanitization
  • Honeypot bot protection
⚡

Performance Optimization

Implemented lazy loading for images, added browser cache headers, minified all CSS, and used Google Fonts with preconnect to cut render-blocking time.

  • Lazy image loading (IntersectionObserver)
  • Font preconnect hints
  • Aggressive cache headers via _headers
  • Minified CSS & JS
  • CDN delivery via GitHub Pages

Deployment & Infrastructure

The site is hosted on GitHub Pages with automatic HTTPS. A _headers file enforces security headers at the CDN level, applied before the response reaches the browser.

  • GitHub Pages (free hosting)
  • Automatic Let's Encrypt SSL
  • _headers file for CDN-level headers
  • IPv6 compatible (GitHub infra)
  • Zero downtime deploys on push

Monitoring & Analysis

Used browser DevTools and Wireshark to analyze traffic. Verified TLSv1.3 handshakes and absence of plaintext HTTP. Documented all findings in the technical report.

  • TLS traffic verified with Wireshark
  • HTTP headers inspected via DevTools
  • Security scan via Mozilla Observatory
  • Response time baseline documented

Project Goal

Why We Built This

This site began as the Project 1 deployment — a simple multi-page website hosted on GitHub Pages demonstrating DNS, IPv4/IPv6, and HTTP vs HTTPS differences.

For Project 2, we expanded it to apply real-world networking concepts: hardening it against common web attacks, optimizing its load performance, and documenting the infrastructure that makes it all work. The goal was to treat it like a production website — because the skills are identical.
